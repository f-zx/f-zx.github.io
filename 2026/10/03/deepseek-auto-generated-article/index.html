deepseek自主生成文章示例

发表于2026-10-03|更新于2026-10-03|示例

这篇文章由 DeepSeek 生成，用途是当一篇”排版试纸”：把博客支持的各类内容都写一遍，方便一眼看出主题、字体、代码高亮有没有问题。

写博客最麻烦的往往不是写作本身，而是不确定某个语法能不能正确渲染。所以这篇示例文章会尽可能覆盖常见写法，你以后写新文章时可以直接来这里复制片段。

一、这篇示例是怎么来的

起因是博客里有两处链接一直是坏的，排查过程中发现了一个很容易踩的坑，值得先记下来：

Hexo 的主题目录 themes/<主题>/source/ 是主题资源区，不是内容区。

放在那里的 .md 文件只会被当成静态资源渲染一遍，不会解析 front-matter、也不会套用页面模板。你写的内容会被原样丢进 HTML，连 --- 都会变成分割线。

正确做法只有一条：自己写的内容一律放在站点根目录的 source/ 下。

判断标准很简单：主题目录是 git clone 来的，升级主题时会 git pull。凡是”升级后不能丢”的东西，都不该放在里面。

分栏 tabs

Hexo 会把 Markdown 一次性渲染成 HTML，访问时不需要服务端参与，所以可以直接托管在 GitHub Pages 上。

优点是快、便宜、几乎不会被攻击。

动态站点每次访问都要查数据库、拼模板，功能更灵活（登录、评论、后台），但需要服务器和运维。

个人博客绝大多数场景用不上这些。

静态站点也能有动态能力：评论用 Giscus/Twikoo 这类第三方服务，搜索用本地索引或 Algolia。

这篇博客目前就是这个思路。

折叠块 hideToggle

点这里展开：为什么中文文件名容易出问题

new_post_name: :title.md 会让文章文件名直接用标题。中文标题本身没问题，但生成的 URL 会被百分号编码成一长串，既不美观，个别部署环境下也容易出岔子。

所以本文的文件名用了英文 deepseek-auto-generated-article.md，标题仍然是中文——文件名管 URL，title 管显示，两者不必一致。
