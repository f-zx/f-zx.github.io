Web 前端期末试卷（A 卷）逐题解析 · 每个选项都讲透

发表于2026-10-31|更新于2026-10-31|期末复习

这是我第一次拿往年 A 卷直接开写的结果——惨不忍睹，几乎全错。

所以我把整份卷子重新做了一遍，每一题、每一个选项都写了解析，并且标注了对应的复习笔记章节。下次考同一张卷子，或者考同一套知识点的卷子，照着这篇过一遍就行。

这篇怎么用

  1. 先看第五部分「编程题」 —— 全卷 40 分，模板最固定，且和（五）编程题模板几乎一一对应。
  2. 再看程序填空 —— 30 分，考的全是 JSON.parse / map / filter / reduce / grid-*，属于”认识 API 就会填”。
  3. 最后看选择、填空 —— 30 分，靠概念辨析，下面每个选项都标了”错在哪”。

文中所有答案以卷末参考答案为准。有 3 处参考答案和题面在原理上对不上，我在对应题目里单独用红框标出了，并说明”按题面应该怎么答、按参考答案又该怎么写”，你自己判断——考试时以题面为准。

全卷结构

题型 题量 单题分 合计
单选题 10 1 10
多选题 5 2（多选少选均不得分） 10
填空题 10 空 1 10
程序填空题 15 空 2 30
编程题 4 8 / 8 / 10 / 14 40
合计 100

一眼就能看出重点：程序填空 + 编程 = 70 分，全是代码。选择和填空 30 分里，真正需要”理解”的只有十来题。

一、单选题（每题 1 分，共 10 分）

10 题 · 10 分逐项拆解

第 1 题 · flex 交叉轴

题目：下列哪个属性可以改变 flex 容器的交叉轴方向？

选项 内容 判断
A flex-wrap ❌ 控制是否换行，与轴方向无关
B flex-flow ❌ 它是 flex-direction + flex-wrap 的简写，间接能改，但单选题要选”最直接”的那个
C flex-direction ✅ 决定主轴方向
D align-items ❌ 控制的是交叉轴上的对齐方式，不是方向

答案：C

为什么 C 对：flex 只有一条主轴、一条交叉轴，交叉轴永远是垂直于主轴的那条。所以只要改变主轴方向（row ↔ column），交叉轴就自动跟着转 90°。flex-direction 就是干这个的。

易错 align-items 和 flex-direction 特别容易混：direction 定方向（轴朝哪），align-items 定对齐（在轴上站哪）。
另外，如果老师的标答记的是 D，请注意——D 只能让元素在交叉轴上靠上/靠下/居中，不可能把交叉轴从竖直变成水平。
口诀 「direction 转轴，justify 沿主轴排队，align 在交叉轴站位。」

📖 对应笔记：（二）CSS 考点全解 · Flex 主轴交叉轴

第 2 题 · 选择器写法

题目：要选择所有 p 标签中 id 为 intro 的元素，正确的选择器是？

选项 写法 选的是什么
A p.intro class 为 intro 的 p
B p#intro id 为 intro 的 p ✅
C p intro p 内部的后代 intro 标签
D p[intro] 带 intro 属性的 p（如 <p intro>）

按题面（说”id 为 intro”）答案应为：B

参考答案给的是 D，这里要辨析 卷末参考答案写 D，但 p[intro] 是属性选择器，选的是"有 intro 这个属性"的元素，和 id 完全无关。
所以要么是题面抄漏了（原题实际问"具有 intro 属性"），要么是答案印错。
判断规则背下来就不会错：. 对应 class，# 对应 id，[] 对应属性。考试时看题面用哪个词，就用哪个符号。
口诀 「点类井号，方括属性」——.class / #id / [attr]。

📖 对应笔记：（二）CSS 考点全解 · 选择器

第 3 题 · 表格表头标签

题目：表格中，用于定义表头单元格的标签是？

选项 内容 判断
A <td> ❌ table data，普通数据单元格
B <th> ✅ table header，表头单元格
C <thead> ❌ 表头区域容器，包住一整个 <tr>，不是单元格
D <thead>（重复） ❌ 同上

答案：B

这题的关键是分清”单元格“和”区域“：

标签 层级 作用
<table> 表格 容器
<thead> / <tbody> 区域 包住若干行
<tr> 行 table row
<th> / <td> 单元格 表头 / 数据

题目问的是”表头单元格“，所以只能是 <th>。

口诀 th = table header（表头格），td = table data（数据格），thead/tbody 是"包行"的区域。

第 4 题 · 媒体查询写法

题目：下列媒体查询写法正确的是？

A @media screen and min-width: 100px {} ❌ 少了括号，必须是 (min-width: 100px)
B @media (width: 768px) and (orientation: landscape) ❌ 语法没错，但 width: 768px 是精确等于，实践上几乎不用，属于”不算错但不推荐”
C @media not screen and (color) ❌ not 用在 screen 前会变成”不是屏幕设备”，和常见响应式意图不符
D @media screen and (max-width: 768px) ✅ 标准写法

答案：D

三个必须记住的点：

  1. 特性必须写在圆括号里 —— (max-width: 768px)，不是 max-width: 768px；
  2. and 用来连接多个条件；

第 5 题 · 数组里的对象怎么取属性

题目：对于 JSON 数组 const arr = [{"name":"王五"},{"name":"赵六"}]，访问第二个元素的 name 属性，正确的是？

选项 写法 判断
A arr.1.name ❌ 语法错误：1 不能跟在点后面
B arr[2]["name"] ❌ 数组下标从 0 开始，[2] 是第三个（越界）
C arr[1].name ✅ 下标 1 = 第二个元素，再点语法取 name
D arr["1"].name ⚠️ 实际能跑（字符串下标会被转成数字），但不是标准写法

答案：C

两层结构要分开看：

两个高频错 ① 下标从 0 开始："第二个" = [1]，不是 [2]；
② 点后面不能跟数字：arr.1 是语法错误，数组只能用方括号。
口诀 「数组数方括号，对象点属性；数组从 0 数，第二个是 [1]。」

第 6 题 · absolute 的参照物

题目：若要使元素完全脱离正常文档流，且定位基准为最近的已定位（非 static）祖先元素，应设置 position 属性为？

选项 内容 参照物 是否脱离文档流
A fixed 浏览器视口 ✅ 脱离
B sticky 最近的滚动容器 ⚠️ 部分脱离（阈值前占位）
C absolute 最近的已定位祖先 ✅ 脱离
D relative 自身原位置 ❌ 不脱离

答案：C

题面给了两个并列条件，必须同时满足：

  1. 完全脱离文档流 → 排除 relative、sticky
  2. 参照最近的已定位祖先 → 排除 fixed（它只认视口）

只有 absolute 两条全中。这也是”父相子绝“这个经典套路的来源：

易错 fixed 也脱离文档流，但它的参照物是视口，不是祖先——看到"最近的已定位祖先"这几个字就要立刻排除 fixed。
另外 sticky 不是完全脱离，它在到达阈值之前仍然占位。

第 8 题 · 实时获取输入框内容用哪个事件

题目：若要实时获取输入框中用户输入的内容，下列事件最适合的是？

选项 事件 触发时机 判断
A click 点击时 ❌ 打字不触发点击
B change 失焦后且值改变时 ❌ 不实时（要等离开输入框）
C keypress 按下字符键时 ⚠️ 敲一个键触发一次，但粘贴、拖动、输入法都不触发；且已被标记废弃
D input 值一变化就触发 ✅ 最全面

答案：D

关键区别在”实时“两个字：

  • change：只有值改变且失去焦点时才触发 → 用户还在打字时你什么也收不到；
  • input：每改一个字符（包括粘贴、删除、中文输入法上屏）都会立刻触发 → 这才是实时。
易错 keypress 看起来"更实时"，但它只处理字符键，粘贴和输入法不触发，而且已经被标准废弃。
判断标准一句话：只要题目出现"实时"，就选 input。

📖 对应笔记：（三）JS 考点（上）· 事件

第 9 题 · grid repeat() 的用法

题目：关于 grid-template-columns: repeat() 的用法，下列说法正确的是？

选项 说法 判断
A repeat(3, 100px) 表示生成 3 列，每列宽度 100px ✅ 正确
B repeat(auto-fill, 1fr) 可实现自动填充列 ❌ 语法错：auto-fill 必须配 minmax() 才有意义，直接写 1fr 无意义
C repeat(2, 100px 200px) 表示生成 100px 和 200px 的各 1 列 ❌ 实际会生成 4 列：100 200 100 200（重复 2 次”100 200”这一组）

第 10 题 · 解构默认值 + 计算

题目：

选项 内容
A 1
B 3
C 4
D undefined

答案：C

数组解构是按位置一一对应的，只给了 [1] 一个值：

变量 对应位置 结果
a [1] 的第 0 项 1
b 第 1 项不存在（undefined） 触发默认值 → 3
c 第 2 项不存在 undefined（没有默认值）

然后 c = a + b = 1 + 3 = 4。

易错 不要把 c 和 b 搞混：默认值只写在 b 后面，所以只有 b 兜底成 3；c 拿到的是 undefined。
中间那步 c = a + b 覆盖了 c 原来的 undefined，这才是最终输出 4 的原因。

第 5 题 · 层叠与优先级

题目：以下关于层叠算法的说法，正确的有：

选项 说法 判断 理由
A 内联样式 > ID 选择器 ✅ 内联权重 1000，ID 只有 100
B 通配符选择器优先级最高 ❌ * 权重是 0，最低
C 同一优先级下，先声明的样式覆盖后声明的 ❌ 说反了，后声明的覆盖先声明的
D 继承的样式优先级低于元素自身样式 ✅ 继承来的样式永远打不过目标元素自己命中的规则
E 类选择器与伪类同级 ✅ 两者都算”类”这一档，权重相同（各 +10）

答案：ADE

完整权重链（必背）：

层级 写法 权重
最高 !important —
1 style="..." 内联 1000
2 #id 100
3 .class、[attr]、:hover 这类伪类 10
4 标签、::before 这类伪元素 1
5 * 通配符 0

C 的错法特别典型：同一优先级时比的是”谁在后面”，后面的赢。因为 CSS 就是从上往下覆盖的，后写的自然生效。

口诀 「权重不同看权重，权重相同看先后；谁在后面谁做主。」

三、填空题（每空 1 分，共 10 分）

第 1 空 · 全大写字母的正则

题目：匹配一个由大写字母组成的字符串（如 "HELLO"），应使用正则表达式 ______。

答案：/^[A-Z]+$/

三部分拆开看：

片段 含义
^ 从开头匹配
[A-Z] 任意一个大写字母
+ 前面的字符至少出现一次（可以多次）
$ 匹配到结尾

为什么必须加 ^ 和 $：不加的话 "abcHELLO123" 也会被判为”包含大写字母”而匹配成功。加了锚点才是”整个字符串只能由大写字母组成“。

易错 ① 忘了锚点 ^...$；② 用 * 而不是 +（* 允许空字符串）；③ 写成 [A-z]——中间是连字符范围，A-z 会把 [ \ ] ^ _ \` 这些符号也包含进来。

📖 对应笔记：（四）JS 考点（下）

第 2 空 · 取第一个 class 匹配的元素

题目：若要使用 CSS 选择器获取第一个匹配 class="center" 的元素，应使用 ______ 函数。

第 2 题 · 补全 Grid 样式（5 空）

题目：

答案

空 答案 判断依据
(1) display 后面是 : grid，开网格的是 display
(2) grid-template-columns 注释写”设置 3 列”
(3) grid-template-rows 注释写”设置 2 行”
(4) grid-row 注释写”占据第 N 行”
(5) grid-column 注释写”占据第 N 列”

逐空解析

  • (1) display：display: grid 开启网格容器，这是 Grid 的第一步。
  • (2) grid-template-columns：columns 是列。值 120px 1fr 1fr = 第一列 120px，剩下两列各分一份剩余空间。三个值 → 3 列。
  • (3) grid-template-rows：rows 是行。80px 1fr → 2 行。
  • (4) grid-row：单个数字表示”占第几行”。grid-row: 1 是第 1 行，grid-row: 2 是第 2 行。

最容易错的是 (5)：为什么是 2/4 而不是 2/3 Grid 里数字指的是网格线（grid line），不是格子。
一个 4 列的网格有 5 条竖线：1 ┃ 2 ┃ 3 ┃ 4 ┃ 5。
"占第 2、3 列" = 从第 2 条线跨到第 4 条线 = 2 / 4。
记住：grid-column: 起点线 / 终点线，终点线 = 起点 + 跨度。
口诀 「columns 是列，rows 是行；grid-row 走纵向，grid-column 走横向；起止写线号，2/4 占两列。」

对着我自己的错题，问题集中在五处，每一处都能靠一张表补救：

薄弱点 表现 怎么补
Grid 的线号 vs 格子 grid-column: 2 / 4 想不通为什么占两列 记住”数字是网格线，不是格子”
数组方法选型 map / filter / reduce 混着用 背”数量变不变”那张判断表
await 要写两次 fetch 后面只 await 一次 记”fetch 拿响应，json 拿数据”
toLowerCase 两边都要转 只转了一边 记”两边都转才不分大小写”
默认值记混 align-items 的默认值写成 flex-start 记 stretch（拉伸），不是 flex-start
最后一句 这张卷子 70 分是"认 API"，30 分是"辨概念"。
